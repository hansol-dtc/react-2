7. state가 필요한 이유

그냥 변수로는 왜 안 되나

7. state가 필요한 이유

            
              function Counter() {
                let count = 0;

                return (
                  <button onClick={() => { count++; }}>
                    {count}
                  </button>
                );
              }

눌러도 계속 0

버튼을 누르면 숫자가 올라갈까요?

값은 실제로 올라간다. 그런데 화면이 안 바뀐다. 왜인지 물어볼 것.

7. state가 필요한 이유

  • 변수는 바뀌었지만 React는 그 사실을 모른다
  • React는 다시 그려야 할 때만 다시 그린다
  • “이 값이 바뀌면 다시 그려라”고 알려줘야 한다
게다가 다시 그려지는 순간 let count = 0 이 다시 실행되어 0으로 돌아간다.

7. state가 필요한 이유

그 도구가 state

8. useState

값이 바뀌면 화면도 바뀌게 하려면

8. useState

          
            import { useState } from 'react';

            const [count, setCount] = useState(0);
            //     현재값   바꾸는 함수      처음값
배열 구조 분해로 두 개를 받는다. 이름은 자유지만 set으로 시작하는 관습을 지킨다.

8. useState

            
              function Counter() {
                const [count, setCount] = useState(0);

                return (
                  <button onClick={() => setCount(count + 1)}>
                    {count}
                  </button>
                );
              }

누르면 올라간다

직접 시연할 것. 1강의 카운터와 js-2 17장의 카운터를 나란히 비교하면 좋다.

8. useState 함정

예상3 증가
실제1 증가

여기서 set을 세 번 부르면 3이 올라갈까요?

한 번 그리는 동안 count는 같은 값으로 고정되어 있다. 그래서 셋 다 같은 계산을 한다.

8. useState 함수로 넘기기

            
              setCount((c) => c + 1);
              setCount((c) => c + 1);
              setCount((c) => c + 1);
실제3 증가
이전 값을 인자로 받는 형태. 이전 값을 바탕으로 계산할 때는 항상 이 형태를 쓰면 안전하다.

8. 정리

  • const [값, set값] = useState(초기값)
  • 바꿀 때는 반드시 set값()
  • set을 부르면 컴포넌트가 다시 실행된다
  • 이전 값이 필요하면 set값(c => ...)

9. 이벤트

사용자 동작에 반응하려면

9. 이벤트 이름

            
              <button onClick={handleClick}>누르기</button>
              <input onChange={handleChange} />
              <form onSubmit={handleSubmit}>
onclickonClick
onchangeonChange
onsubmitonSubmit
HTML의 onclick과 달리 낙타등 표기. 값은 문자열이 아니라 함수다.

9. 이벤트 괄호

            
              {/* 함수를 넘김 */}
              <button onClick={handleClick}>

              {/* 즉시 실행됨 */}
              <button onClick={handleClick()}>
괄호를 붙이면
렌더링할 때 바로 실행된다

둘 중 어느 쪽이 맞을까요?

가장 흔한 실수. 무한 루프의 원인이 되기도 한다.

9. 이벤트 인자 넘기기

            
              function Counter() {
                const [count, setCount] = useState(0);

                return (
                  <>
                    <button onClick={() => setCount(c => c + 1)}>
                      +
                    </button>
                    <button onClick={() => setCount(c => c - 1)}>
                      -
                    </button>
                    <p>{count}번</p>
                  </>
                );
              }

3번

인자를 넘겨야 하면 화살표 함수로 감싼다. react_dtc의 예제와 같은 코드.

9. 정리

  • onClick 처럼 낙타등 표기
  • 값은 함수. 괄호를 붙이면 즉시 실행된다
  • 인자가 필요하면 () => 함수(인자)

10. 불변성

배열과 객체 state를 바꾸려면

10. 불변성 push 금지

            
              const [todos, setTodos] = useState([]);

              todos.push("우유 사기");   // 하면 안 된다
배열은 바뀌었지만
화면이 안 바뀐다

여기서 push를 쓰면 화면이 바뀔까요?

React는 값이 바뀌었는지 "같은 것인지"로 판단한다. push는 같은 배열을 고칠 뿐이라 알아채지 못한다.

10. 불변성 새 배열

            
              setTodos([...todos, "우유 사기"]);
  • 우유 사기
스프레드로 기존 항목을 펼치고 새 항목을 붙여 새 배열을 만든다.

10. 불변성 세 가지

            
              // 추가
              setTodos([...todos, 새항목]);

              // 삭제
              setTodos(todos.filter((t) => t.id !== id));

              // 수정
              setTodos(todos.map((t) =>
                t.id === id ? { ...t, done: true } : t
              ));
추가스프레드
삭제filter
수정map
이 세 패턴이 실무의 대부분이다. 통째로 외워두면 편하다.

10. 불변성 객체

            
              const [user, setUser] = useState({
                name: "추희도", age: 20
              });

              setUser({ ...user, age: 21 });
name"추희도"
age21
객체도 같다. 기존 것을 펼치고 바꿀 것만 덮어쓴다.

10. 정리

  • state는 고치지 말고 새로 만든다
  • push, splice 대신 스프레드
  • 추가는 [...], 삭제는 filter, 수정은 map

11. 폼과 입력

입력창의 값을 다루려면

11. 폼과 입력 제어 컴포넌트

            
              const [text, setText] = useState("");

              <input
                value={text}
                onChange={(e) => setText(e.target.value)}
              />
              <p>{text}</p>

안녕

value는 state에서, 바뀌면 state를 고친다. 이 왕복이 제어 컴포넌트의 핵심.

11. 폼과 입력 함정

            
              <input value={text} />   {/* onChange 없음 */}
글자를 쳐도 아무것도 안 써진다
value가 state에 묶여 있기 때문

onChange를 빼면 글자가 써질까요?

value만 주고 onChange를 빼먹는 실수. 입력이 막힌 것처럼 보인다.

11. 폼과 입력 submit

            
              function TodoForm({ onAdd }) {
                const [text, setText] = useState("");

                function handleSubmit(e) {
                  e.preventDefault();
                  onAdd(text);
                  setText("");
                }

                return <form onSubmit={handleSubmit}>...</form>;
              }
preventDefault를 빼면 페이지가 새로고침된다. 제출 후 입력창을 비우는 것도 잊지 말 것.

11. 정리

  • value 와 onChange 는 항상 짝
  • 입력값은 e.target.value
  • submit에서는 e.preventDefault()

12. 상태 끌어올리기

여러 컴포넌트가 한 값을 함께 쓰려면

12. 상태 끌어올리기 문제

<App> ├─ <TodoForm> 새 할 일을 만든다 └─ <TodoList> 할 일을 보여준다

형제끼리는 값을 주고받을 수 없다

props는 아래로만 흐른다. 옆으로는 못 간다.

12. 상태 끌어올리기

둘의 공통 부모로
state를 올린다

12. 상태 끌어올리기

            
              function App() {
                const [todos, setTodos] = useState([]);

                function addTodo(text) {
                  setTodos([...todos, { id: Date.now(), text }]);
                }

                return (
                  <>
                    <TodoForm onAdd={addTodo} />
                    <TodoList todos={todos} />
                  </>
                );
              }
  • 우유 사기
값은 아래로(props), 변경은 위로(함수를 props로 내려서). 이 흐름이 React의 기본 구조다.

12. 정리

  • 값은 아래로 — props
  • 변경은 위로 — 함수를 props로 내려준다
  • 공유가 필요하면 공통 부모로 state를 올린다
